# سيكو سيكو

> الخطة الرئيسية المتكاملة لنظام إدارة الشراء والمخزون بالوزن والتوزيع على التصريف والتحصيل والربحية والشراكة وإعادة الاستثمار

**النسخة 6.0 - المخطط التشغيلي النهائي قبل المواصفات التقنية**

---

## 1. الهدف من النظام

بناء نظام واحد يدير دورة النشاط كاملة من لحظة شراء الصنف بالوزن والقيمة وحتى توزيعه على الموزعين على التصريف، ثم تسجيل المبيعات والتحصيلات والمرتجعات وحساب الربح لكل جرام ولكل دفعة ولكل موزع. ويضاف إلى ذلك إدارة الشراكة بين شريكين بصورة مستقلة وشفافة، بحيث يعرف النظام في أي وقت رأس مال كل شريك، نسبة أرباحه، ما استحقه من أرباح، ما سحبه، وما بقي له.

## 2. المبادئ المحاسبية الأساسية

- كل عملية شراء تنشئ دفعة مستقلة حتى لو كان الصنف نفسه، لأن تكلفة الجرام قد تختلف من دفعة إلى أخرى.

- تسليم كمية للموزع على التصريف ينقل الوزن إلى عهدة الموزع ولا يعتبر تحصيلاً نقدياً.

- يفصل النظام بين الربح المتوقع، والربح المحقق، والمبلغ المستحق، والنقد المحصل.

- يفصل النظام أيضاً بين رأس مال النشاط، وأرباح النشاط، وحساب كل شريك، والسحوبات الشخصية.

- لا يجوز اعتبار سحب الشريك مصروفاً تشغيلياً؛ بل يسجل في محفظته الشخصية ويؤثر على رصيده المستحق له.

## 3. المثال الأساسي للحساب

| البند                  | القيمة                       |
|-----------------------------------------------|-----------------------------------------------------|
| شراء دفعة              | 1,200 جرام بقيمة 21,000 ريال |
| تكلفة الجرام           | 17.50 ريال                   |
| تسليم موزع             | 500 جرام بقيمة 12,000 ريال   |
| قيمة الجرام للموزع     | 24.00 ريال                   |
| تكلفة الـ 500 جرام     | 8,750 ريال                   |
| الربح المتوقع          | 3,250 ريال                   |
| الربح المتوقع لكل جرام | 6.50 ريال                    |

## 4. دورة العمل التشغيلية

- إنشاء الصنف وكوده ووصفه.

- تسجيل الشراء: الصنف، الوزن، القيمة، التاريخ، المورد والمصاريف المرتبطة.

- إنشاء رقم دفعة وحساب تكلفة الجرام آلياً.

- إدخال الكمية إلى المخزون المتاح.

- إنشاء ملف الموزع وحد العهدة وحالة حسابه.

- تسليم كمية من دفعة محددة للموزع بقيمة متفق عليها.

- تسجيل ما تم تصريفه فعلياً من العهدة.

- تسجيل التحصيلات الجزئية أو الكاملة وربطها بالمستحقات.

- إرجاع أي كمية غير مباعة إلى نفس الدفعة.

- احتساب الربح المحقق والمتوقع والأرصدة آلياً.

- تحديد الجزء الذي سيبقى في النشاط أو يعاد استثماره أو يصبح متاحاً للتوزيع على الشركاء.

## 5. إدارة الشراكة — وحدة رئيسية جديدة

المشروع مملوك لشريكين، ولذلك يجب أن تكون إدارة الشركاء جزءاً أساسياً من النظام وليست مجرد تقرير. أسماء الشركاء ونسبهم وقواعد توزيع الأرباح يجب أن تكون قابلة للتعديل من الإعدادات، مع الاحتفاظ بتاريخ أي تغيير حتى لا تتأثر الفترات السابقة.

### 5.1 إعدادات الشركاء

| الإعداد              | التصميم المطلوب                                 |
|---------------------------------------------|------------------------------------------------------------------------|
| اسم الشريك           | قابل للتعديل من الإعدادات                       |
| رقم/كود الشريك       | معرف داخلي ثابت حتى لو تغير الاسم               |
| نسبة ملكية رأس المال | مثلاً 50% / 50% أو أي نسبة أخرى                  |
| نسبة توزيع الأرباح   | يمكن أن تساوي الملكية أو تختلف عنها حسب الاتفاق |
| تاريخ سريان النسبة   | إلزامي عند تغيير النسب                          |
| الرصيد الافتتاحي     | رأس المال أو أي مستحق افتتاحي لكل شريك          |
| حالة الشريك          | نشط / غير نشط                                   |

مهم: لا يتم تعديل النسبة القديمة بأثر رجعي. أي تغيير ينشئ نسخة جديدة من اتفاق الشراكة بتاريخ سريان محدد، وتبقى الأرباح السابقة محسوبة وفق النسبة التي كانت سارية وقت استحقاقها.

### 5.2 محفظة مستقلة لكل شريك

لكل شريك صفحة ومحفظة مستقلة تعرض جميع حركاته. المحفظة ليست حساباً بنكياً فقط، بل دفتر حساب شريك كامل يوضح ما له وما عليه.

| المؤشر                   | المعنى                                                             |
|-------------------------------------------------|-------------------------------------------------------------------------------------------|
| رأس المال المساهم به     | إجمالي ما ضخه الشريك كرأس مال                                      |
| نسبة الربح               | النسبة المعتمدة له في الفترة                                       |
| الأرباح المستحقة         | حصته من الأرباح القابلة للتوزيع                                    |
| السحوبات                 | كل مبلغ أخذه الشريك من النشاط                                      |
| إيداعات إضافية           | أي مبالغ أضافها بعد رأس المال الأولي                               |
| تسويات                   | أي تعديل معتمد مع سبب واضح                                         |
| الرصيد المستحق للشريك    | الأرباح المستحقة + المبالغ المستردة/المضافة حسب السياسة - السحوبات |
| الأرباح غير المسحوبة     | حصته المستحقة التي ما زالت داخل النشاط                             |
| الأرباح المعاد استثمارها | الجزء الذي اختار الشريك إبقاءه وإعادة ضخه في النشاط                |

### 5.3 أنواع سحب الشريك

عند تسجيل سحب يجب ألا يكتفي النظام بحقل مبلغ فقط. يجب تحديد نوع السحب لأن أثره المحاسبي يختلف:

- سحب من الأرباح: يخفض الأرباح المستحقة وغير المسحوبة للشريك.

- سحب على الحساب / مقدم أرباح: يسجل كسحب مسبق ويخصم من استحقاقات الشريك القادمة.

- استرداد جزء من رأس المال: يخفض حساب رأس مال الشريك ويحتاج اعتماداً خاصاً.

- سحب أو تسوية أخرى: يحتاج سبباً إلزامياً واعتماد المدير.

### 5.4 شاشة تسجيل السحب

| الحقل            | المطلوب                              |
|-----------------------------------------|-------------------------------------------------------------|
| الشريك           | اختيار الشريك                        |
| التاريخ          | تاريخ السحب                          |
| المبلغ           | قيمة السحب                           |
| نوع السحب        | أرباح / مقدم أرباح / رأس مال / تسوية |
| طريقة الدفع      | نقد / تحويل / أخرى                   |
| المرجع           | رقم تحويل أو مرجع اختياري            |
| الملاحظات        | سبب أو وصف الحركة                    |
| الرصيد قبل السحب | يظهر آلياً                            |
| الرصيد بعد السحب | معاينة آلية قبل الحفظ                |
| المرفق           | إيصال أو صورة تحويل عند الحاجة       |
| الاعتماد         | حسب الصلاحيات وقيمة الحركة           |

### 5.5 توزيع الأرباح

لا يوزع النظام الأرباح بمجرد وجود ربح متوقع. يجب إنشاء عملية «إقفال/توزيع أرباح» لفترة محددة، مثلاً شهرياً أو عند طلب الشركاء. العملية تحسب الربح القابل للتوزيع ثم توزعه حسب نسب الأرباح السارية.

- الربح المحقق للفترة = الإيراد المحقق ناقص تكلفة الكميات المباعة والمصاريف المعتمدة.

- يمكن الاحتفاظ باحتياطي أو مبلغ داخل النشاط قبل التوزيع.

- الربح القابل للتوزيع = الربح المحقق - الاحتياطي/المبلغ المحتفظ به - أي التزامات محددة.

- حصة الشريك = الربح القابل للتوزيع × نسبة أرباح الشريك السارية.

- بعد اعتماد التوزيع، تضاف الحصة إلى محفظة الشريك كـ«ربح مستحق».

- يمكن للشريك سحبها أو إبقاؤها أو تحويلها إلى «أرباح معاد استثمارها».

### 5.6 مثال للشراكة

| المثال                  | النتيجة           |
|------------------------------------------------|------------------------------------------|
| الربح القابل للتوزيع    | 20,000 ريال       |
| نسبة الشريك الأول       | 60% = 12,000 ريال |
| نسبة الشريك الثاني      | 40% = 8,000 ريال  |
| سحب الشريك الأول سابقاً  | 5,000 ريال        |
| المتبقي المستحق للأول   | 7,000 ريال        |
| سحب الشريك الثاني سابقاً | 2,000 ريال        |
| المتبقي المستحق للثاني  | 6,000 ريال        |

إذا كان أحد السحوبات «مقدم أرباح» قبل إقفال الفترة، يظهر كرصد مدين على محفظة الشريك ثم تتم تسويته تلقائياً عند اعتماد حصته من الأرباح.

## 6. لوحة تحكم الشراكة

- بطاقة مستقلة لكل شريك: الاسم، نسبة الملكية، نسبة الأرباح، رأس المال، الأرباح المستحقة، السحوبات، الأرباح المعاد استثمارها، والمتبقي له.

- إجمالي حقوق الشركاء مع مقارنة بين الشريكين.

- رسم لحركة السحوبات شهرياً.

- تاريخ آخر توزيع أرباح وقيمة التوزيع.

- الأرباح المتاحة للتوزيع حالياً مقابل الأرباح المحتفظ بها في النشاط.

- تنبيه إذا تجاوزت سحوبات شريك أرباحه المستحقة.

- تنبيه عند وجود مقدم أرباح غير مسوى.

- إظهار نسبة ما أعاد كل شريك استثماره من أرباحه.

## 7. إعادة الاستثمار

يجب أن يتيح النظام قراراً واضحاً لكل حصة أرباح: سحب، إبقاء كرصيد مستحق، أو إعادة استثمار. عند إعادة الاستثمار، تنشأ حركة من محفظة الشريك إلى محفظة رأس المال/إعادة الاستثمار، مع الاحتفاظ بالمصدر حتى يمكن معرفة مقدار رأس المال الذي تكوّن من الأرباح لكل شريك.

| الحركة              | الأثر                                                       |
|--------------------------------------------|------------------------------------------------------------------------------------|
| ربح مستحق للشريك    | يزيد رصيد محفظة الشريك                                      |
| سحب أرباح           | يخفض رصيد محفظة الشريك ويخفض النقد                          |
| إعادة استثمار       | يخفض الربح المتاح للسحب ويزيد رصيد الاستثمار المنسوب للشريك |
| إضافة رأس مال جديدة | تزيد رأس مال الشريك ولا تعتبر ربحاً                          |
| استرداد رأس مال     | يخفض رأس مال الشريك بعد الاعتماد                            |

## 10. التقارير الإضافية للشركاء

- كشف حساب كامل لكل شريك من بداية النشاط وحتى تاريخ محدد.

- تقرير الأرباح المستحقة والموزعة والمسحوبة والمتبقية لكل شريك.

- تقرير رأس المال: مساهمة كل شريك، الإضافات، الاستردادات والرصيد الحالي.

- تقرير السحوبات حسب الشريك والفترة والنوع.

- تقرير الأرباح المعاد استثمارها حسب الشريك والدفعات التي تم تمويلها.

- تقرير مقارنة الشريكين.

- تقرير تاريخ تغير نسب الملكية والأرباح.

- تقرير الأرباح القابلة للتوزيع قبل تنفيذ أي توزيع.

## 11. الحوكمة والضوابط

- تغيير أسماء الشركاء مسموح من الإعدادات، لكن معرف الشريك الداخلي لا يتغير.

- تغيير نسبة الملكية أو الأرباح يحتاج تاريخ سريان ولا يعيد حساب الفترات المقفلة.

- إقفال توزيع الأرباح يحتاج اعتماداً، وبعد الاعتماد لا يعدل مباشرة؛ التصحيح بحركة عكسية.

- لا يسمح بسحب من رأس المال بنفس صلاحية سحب الأرباح؛ استرداد رأس المال عملية حساسة مستقلة.

- إذا تجاوز مقدم الأرباح رصيد الشريك، يظهر تحذير واضح ويمكن منع العملية حسب إعداد النظام.

- كل سحب أو إيداع أو توزيع أو إعادة استثمار يظهر في سجل التدقيق.

- لا يجوز حذف حركة شريك معتمدة؛ يتم عكسها مع توضيح السبب.

- يجب أن يتطابق مجموع محافظ الشركاء مع حسابات حقوق الشركاء في النظام.

## 13. تجربة المستخدم والشاشات

- واجهة عربية كاملة من اليمين إلى اليسار على الجوال والكمبيوتر.

- Dashboard رئيسية للنشاط، مع تبويب مستقل «الشركاء».

- صفحة الشريك تعرض بطاقة ملخص ثم دفتر الحركات بالتسلسل الزمني.

- زر سريع «تسجيل سحب شريك» مع معاينة الرصيد قبل وبعد.

- شاشة «إقفال وتوزيع الأرباح» تعرض الحسابات قبل الاعتماد ولا تسمح بالتوزيع الصامت.

- صفحة إعادة الاستثمار تسمح بتحديد حصة كل شريك التي ستبقى في النشاط.

## 16. قرارات يفضل جعلها إعدادات قابلة للتغيير

- هل الربح يعتبر مستحقاً عند البيع أم بعد التحصيل؟ يفضل أن يحتفظ النظام بالمقياسين.

- دورية توزيع الأرباح: شهري، ربع سنوي، أو عند الطلب.

- هل يوجد احتياطي إلزامي قبل توزيع الأرباح؟

- هل يسمح بمقدم أرباح؟ وما الحد الأقصى لكل شريك؟

- هل نسبة الأرباح دائماً مساوية لنسبة الملكية أم يمكن أن تختلف؟

- هل إعادة الاستثمار تغير نسبة الملكية أم تسجل كرأس مال/حساب جاري للشريك فقط؟ هذه نقطة يجب تثبيتها قانونياً ومحاسبياً قبل جعلها تغير الملكية.

- هل المصاريف والنقل والتخزين تدخل في تكلفة الدفعة؟

## 17. تعليمات مباشرة لفريق Claude Coding

اعتبر هذه الوثيقة مصدر الحقيقة للنظام. ابدأ بتصميم مخطط قاعدة البيانات والعلاقات، ثم قواعد الأعمال، ثم واجهات المستخدم. يجب أن يكون تتبع الدفعات والعهد ومحافظ الشركاء وسجل التدقيق جزءاً من النواة وليس إضافات لاحقة. جميع الحسابات المالية والمخزنية تنفذ في طبقة الخادم/قاعدة البيانات أيضاً. لا تسمح بتعديل الفترات المقفلة أو نسب الشركاء بأثر رجعي. أنشئ اختبارات آلية للشراء والتوزيع والتحصيل وتوزيع الأرباح والسحوبات وإعادة الاستثمار قبل الإطلاق.

## 18. إدارة الصفقة مع الموزع - Deal Management

من الآن يجب اعتبار كل مرة يتم فيها تسليم كمية لموزع كـ «صفقة مستقلة» داخل النظام. الصفقة تكون حاوية كاملة لكل ما يتعلق بهذه الكمية من لحظة التسليم وحتى السداد الكامل والإغلاق. لا تضيع أي حركة بين شاشات منفصلة؛ كل بيع، تحصيل، استرداد كمية، تسوية أو ملاحظة يظهر داخل نفس ملف الصفقة وبترتيب زمني واضح.

### 18.1 إنشاء الصفقة تلقائياً عند تسليم الكمية

| الحقل                | المطلوب                                                   |
|---------------------------------------------|----------------------------------------------------------------------------------|
| رقم الصفقة           | رقم تلقائي فريد مثل DEAL-2026-0001                        |
| الموزع               | الموزع المستلم للكمية                                     |
| الصنف / الدفعة       | ربط مباشر بالـ Lot الذي خرجت منه الكمية                   |
| الوزن المسلم         | الوزن الأصلي للصفقة بالجرام                               |
| تكلفة رأس المال      | تكلفة الكمية من سعر الشراء الفعلي للدفعة                  |
| قيمة الصفقة          | القيمة المتفق أن يسددها الموزع بعد التصريف                |
| الربح المتوقع        | قيمة الصفقة ناقص تكلفة رأس المال                          |
| تكلفة الجرام         | تكلفة الشراء الفعلية للجرام                               |
| قيمة الصفقة للجرام   | قيمة الصفقة ÷ الوزن الأصلي                                |
| الربح المتوقع للجرام | الفرق بين القيمتين                                        |
| تاريخ التسليم        | تاريخ بداية الصفقة                                        |
| تاريخ الاستحقاق      | اختياري أو حسب سياسة الموزع                               |
| حالة الصفقة          | مفتوحة / جزئية / مسددة / مغلقة / متعثرة / ملغاة بعكس حركة |

### 18.2 ملف الصفقة الموحد

- رأس الصفحة يعرض الوزن الأصلي، الوزن الحالي لدى الموزع، الوزن المسترد، الوزن المصرف/المباع، وتكلفة رأس المال المتبقية.

- يعرض القيمة الأصلية للصفقة، القيمة المعدلة بعد استرداد كميات، إجمالي ما سدده الموزع، والمتبقي عليه.

- يعرض الربح المتوقع الأصلي والربح المتوقع الحالي بعد الاستردادات والتسويات.

- يحتوي Timeline لكل الأحداث: تسليم، بيع/تصريف، دفعة مالية، استرداد كمية، تعديل معتمد، ملاحظة، إغلاق.

- يسمح بإرفاق صور إيصالات أو تحويلات أو أي مستند مرتبط بالصفقة.

- كل حدث داخل الصفقة له مستخدم وتاريخ ووقت ومرجع واضح ولا يمكن حذفه بعد الاعتماد.

### 18.3 منطق استرداد كمية من الموزع

استرداد الكمية ليس دفعة مالية من الموزع، ولا يجب أن يعامل كبيع أو تحصيل. هو عكس جزئي لتسليم المخزون: الكمية تعود إلى المخزون بنفس تكلفة رأس المال الأصلية، وفي الوقت نفسه تنخفض القيمة المتوقعة للصفقة والربح المتوقع بنسبة الكمية المستردة وفق اقتصاديات الصفقة الأصلية.

مثال: تم تسليم موزع 500 جرام. تكلفة هذه الكمية عليك 10,000 ريال، وقيمة الصفقة المتفق عليها 12,000 ريال. إذن تكلفة الجرام = 20 ريال، وقيمة الصفقة للجرام = 24 ريال، والربح المتوقع = 4 ريالات لكل جرام. إذا استرددت 100 جرام من الموزع، يتم احتساب الاسترداد من «تكلفة رأس المال الأصلية» وليس على أنه تحصيل بقيمة البيع.

| البند                | قبل الاسترداد | استرداد 100 جرام          | بعد الاسترداد |
|---------------------------------------------|--------------------------------------|--------------------------------------------------|--------------------------------------|
| الوزن                | 500 جرام      | 100 جرام                  | 400 جرام      |
| رأس المال المرتبط    | 10,000        | 2,000 يعود للمخزون        | 8,000         |
| قيمة الصفقة المتوقعة | 12,000        | 2,400 تخفض من قيمة الصفقة | 9,600         |
| الربح المتوقع        | 2,000         | 400 يخفض من الربح المتوقع | 1,600         |
| المبلغ المسدد نقداً   | 0             | 0                         | 0             |

المعادلات: تكلفة الكمية المستردة = الوزن المسترد × تكلفة الجرام الأصلية للدفعة. الربح المتوقع الملغى = الوزن المسترد × الربح المتوقع للجرام في الصفقة. التخفيض في قيمة الصفقة = تكلفة الكمية المستردة + الربح المتوقع الملغى. بذلك لا يتم تسجيل الـ100 جرام كسداد نقدي، بل كاسترداد مخزون يخفض رأس المال والربح المتوقع المرتبطين بالصفقة.

### 18.4 قواعد الاسترداد

- لا يمكن استرداد وزن أكبر من الوزن غير المصرف والمتبقي فعلياً لدى الموزع في الصفقة.

- الكمية المستردة تعود إلى نفس الدفعة الأصلية ما لم توجد عملية تحويل مخزون معتمدة.

- سعر رأس المال للكمية المستردة لا يعاد احتسابه من سعر البيع؛ يستخدم Cost per Gram للدفعة الأصلية.

- الاسترداد يخفض الربح المتوقع ولا يؤثر على الربح المحقق من الكميات التي سبق بيعها أو تحصيلها.

- إذا كانت الصفقة قد شهدت استردادات متعددة، يحافظ النظام على كل استرداد كحركة مستقلة وتظهر جميعها في التقرير.

- إذا تم استرداد كامل الكمية غير المباعة وبقي رصيد مالي مسدد أو مستحق، النظام يمنع الإغلاق حتى تتم التسوية المحاسبية الواضحة.

### 18.5 التحصيل داخل الصفقة

- كل مبلغ يستلمه النظام من الموزع يمكن ربطه مباشرة بصفقة محددة أو توزيعه على عدة صفقات مفتوحة بموافقة المستخدم.

- داخل الصفقة يظهر: إجمالي القيمة المعدلة للصفقة، إجمالي المسدد، المتبقي، نسبة السداد، وآخر تاريخ سداد.

- يدعم النظام دفعات جزئية متعددة دون إغلاق الصفقة.

- لا تغلق الصفقة تلقائياً إلا عندما يصبح الرصيد المالي صفراً ويتم تسوية كل الوزن: إما مباع/مصرف أو مسترد أو مسوى بحركة معتمدة.

- إذا تم سداد الصفقة بالكامل وما زال وزن غير مسوى لدى الموزع، تظهر حالة «مسددة مالياً - غير مغلقة مخزنياً» حتى تتم تسوية الوزن.

### 18.6 حالات الصفقة المقترحة

| الحالة                          | المعنى                                                       |
|--------------------------------------------------------|-------------------------------------------------------------------------------------|
| Draft                           | تم تجهيز الصفقة ولم يتم تسليمها بعد                          |
| Open                            | تم التسليم ولا يوجد إغلاق                                    |
| Partially Settled               | يوجد سداد جزئي أو تصريف جزئي                                 |
| Partially Returned              | تم استرداد جزء من الكمية                                     |
| Paid - Stock Pending            | القيمة مسددة لكن الوزن لم تتم تسويته بالكامل                 |
| Stock Settled - Payment Pending | الوزن مسوى لكن يوجد مبلغ متبقي                               |
| Closed                          | الرصيد المالي = صفر والوزن = صفر بعد البيع/الاسترداد/التسوية |
| Overdue                         | تجاوز تاريخ الاستحقاق وما زال هناك مبلغ مستحق                |
| Reversed                        | تم عكس الصفقة بحركة نظامية معتمدة                            |

### 19.1 مؤشرات الصفقة داخل الشاشة

- نسبة السداد = إجمالي المسدد ÷ القيمة المعدلة الحالية للصفقة.

- نسبة تسوية الوزن = (الوزن المباع + الوزن المسترد + الوزن المسوى المعتمد) ÷ الوزن الأصلي.

- الرصيد المالي المتبقي = القيمة المعدلة - إجمالي المسدد - أي خصومات مالية معتمدة.

- الوزن المفتوح = الوزن الأصلي - المباع - المسترد - المسوى.

- رأس المال المفتوح = تكلفة الجرام × الوزن المفتوح.

- الربح المتوقع المفتوح = ربح الجرام المتوقع × الوزن المفتوح، مع مراعاة أي نموذج تسعير خاص للصفقة.

## 21. ضوابط إغلاق الصفقة

- لا يسمح بإغلاق الصفقة إذا كان الرصيد المالي لا يساوي صفراً إلا إذا وجدت تسوية نهائية معتمدة.

- لا يسمح بالإغلاق إذا بقي وزن مفتوح لدى الموزع دون حالة واضحة.

- الإغلاق ينشئ Snapshot نهائي للكمية والتكلفة والربح والتحصيلات حتى لا تتغير نتيجة الصفقة لاحقاً بصمت.

- أي تصحيح بعد الإغلاق يحتاج إعادة فتح بصلاحية مدير أو حركة عكسية، مع سجل تدقيق كامل.

- التقرير النهائي للصفقة بعد الإغلاق يحمل رقم النسخة وتاريخ الإصدار ويمكن إعادة طباعته دون تغيير البيانات الأصلية.

## 22. التكامل بين الصفقة ومحفظة الشركاء

أرباح الصفقة لا تنتقل مباشرة إلى محافظ الشركاء عند مجرد إنشاء الصفقة. الربح المتوقع يظهر للتحليل فقط. عندما يصبح الربح محققاً وفق سياسة النظام، يدخل ضمن أرباح الفترة القابلة للإقفال، وبعد اعتماد توزيع الأرباح فقط يتم تخصيص حصة كل شريك في محفظته. بذلك تبقى الصفقة والمخزون والتحصيل والشراكة مترابطة دون خلط بين المراحل.

## 23. تحديث تعليمات Claude Coding

يجب أن يكون كيان Deal هو محور دورة التوزيع على الموزعين. إنشاء أي Consignment يجب أن ينشئ Deal أو Deal Line مرتبطاً به. جميع عمليات البيع والتحصيل والاسترداد والتسوية تمر عبر الصفقة وتحدث أرصدتها بطريقة Transactional. لا تعتمد على حسابات الواجهة؛ نفذ قيود الوزن والتكلفة والإغلاق في قاعدة البيانات/الخادم. استخدم المثال 500 جرام: تكلفة 10,000 وقيمة صفقة 12,000 ثم استرداد 100 جرام كاختبار Unit/Integration إلزامي، وتحقق أن رأس المال يعود 2,000 وأن الربح المتوقع ينخفض 400 وأن المبلغ المسدد يبقى صفراً.

## إضافة V5 - سياسة التقارير الخارجية والداخلية

يجب فصل تقارير النظام إلى نوعين مختلفين تماماً: تقرير داخلي للشركة يمكن أن يحتوي الربحية والتكلفة ورأس المال ومؤشرات الأداء، وتقرير خارجي للموزع لا يكشف أي معلومة تخص أرباح الشركة أو تكلفة الشراء أو رأس المال أو هامش الربح. الهدف أن يخرج تقرير الموزع ككشف صفقة واضح واحترافي، لكنه لا يكشف أسرار الشركة المالية.

### 1. سؤال إلزامي قبل إنشاء التقرير

عند ضغط المستخدم على «إنشاء تقرير صفقة» أو «تصدير كشف للموزع»، يعرض النظام اختياراً واضحاً قبل التوليد:

| الخيار               | ما الذي يظهر                                                                                                                                                                  |
|---------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| تقرير داخلي - للشركة | كل تفاصيل الصفقة بما فيها التكلفة، رأس المال، الربح المتوقع، الربح المحقق، ربح الجرام، هوامش الربح، المصاريف، وأي مؤشرات داخلية.                                              |
| تقرير خارجي - للموزع | فقط معلومات التعامل بين الشركة والموزع: الكميات، القيم المتفق عليها، الدفعات، المستردات، الرصيد المتبقي، وحالة الصفقة. لا تظهر أي تكلفة شراء أو ربح أو هامش أو معلومات شراكة. |

يمكن إضافة إعداد افتراضي في النظام، ولكن حتى لو كان هناك إعداد افتراضي، يفضل أن يؤكد المستخدم نوع التقرير عند كل تصدير لتقليل احتمال إرسال تقرير داخلي بالخطأ.

### 2. محتوى التقرير الخارجي للموزع

التقرير الخارجي يجب أن يكون عملياً ومفهوماً للموزع، ويعرض فقط ما يخص الصفقة بين الطرفين.

- رقم الصفقة وتاريخ بدايتها وحالتها الحالية.

- اسم الموزع وبياناته الأساسية.

- اسم الصنف أو وصف الكمية المسلمة، بدون إظهار تكلفة الشركة الأصلية.

- الوزن الذي تم تسليمه للموزع عند بداية الصفقة.

- القيمة الإجمالية المتفق عليها للصفقة.

- كل دفعة قام الموزع بسدادها: التاريخ، المبلغ، طريقة الدفع، والمرجع إن وجد.

- إجمالي ما تم سداده حتى تاريخ التقرير.

- المبلغ المتبقي على الصفقة.

- أي كمية تم استردادها من الموزع: التاريخ، الوزن المسترد، ووصف الحركة.

- أثر الاسترداد على الرصيد التجاري للصفقة وفق القاعدة المعتمدة، بدون إظهار تكلفة رأس المال الداخلية أو الربح الذي تم إلغاؤه.

- الوزن المتبقي لدى الموزع إذا كانت الصفقة ما زالت مفتوحة.

- سجل مختصر لحركات الصفقة التي تخص الموزع.

- حالة الصفقة: مفتوحة، جزئياً مسددة، مسددة، بانتظار تسوية كمية، أو مغلقة.

- تاريخ الإغلاق إذا تم إغلاق الصفقة بالكامل.

### 3. معلومات ممنوع ظهورها في تقرير الموزع

- سعر شراء الشركة للصنف أو الدفعة.

- تكلفة الجرام الداخلية.

- رأس المال المستخدم في الصفقة.

- الربح المتوقع أو الربح المحقق.

- ربح الشركة لكل جرام.

- هامش الربح أو نسبة العائد.

- المصاريف الداخلية أو تكلفة التشغيل إلا إذا كانت بنداً تجارياً متفقاً عليه مع الموزع.

- أي معلومات تخص الشريكين أو نسب أرباحهما أو سحوباتهما أو محافظهما.

- إجمالي أرباح الشركة أو أرصدتها أو رأس مالها.

- أي مقارنة داخلية بين الموزعين أو تقييم لأداء الموزع.

### 4. محتوى التقرير الداخلي للشركة

التقرير الداخلي هو النسخة الكاملة للصفقة ويجب أن يتيح للإدارة معرفة الوضع المالي الحقيقي من البداية حتى الإغلاق.

- كل بيانات التقرير الخارجي للموزع.

- الدفعة الأصلية التي جاءت منها الكمية وتكلفة الجرام.

- تكلفة رأس المال للكمية المسلمة.

- قيمة الصفقة وسعر الجرام التجاري.

- الربح المتوقع في بداية الصفقة.

- أثر كل كمية مستردة على رأس المال والربح المتوقع.

- الربح المحقق حتى تاريخه.

- المبلغ المحصل فعلياً والمبلغ المستحق.

- الوزن المباع أو المسوى أو المسترد والمتبقي.

- المصاريف المباشرة المرتبطة بالصفقة إن وجدت.

- صافي ربح الصفقة وربح الجرام بعد جميع التسويات.

- حالة التحصيل والمدة التي استغرقتها الصفقة حتى الإغلاق.

- أي ملاحظات داخلية أو تقييم أداء الموزع.

### 5. منطق الاسترداد داخل التقرير الخارجي والداخلي

إذا كانت الصفقة 500 جرام بقيمة تجارية 12,000 ريال، وكانت تكلفة الشركة للـ500 جرام 10,000 ريال، ثم استردت الشركة 100 جرام من الموزع:

| البند                                            | التقرير الداخلي                              | تقرير الموزع                                                                          |
|-------------------------------------------------------------------------|---------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| الوزن المسترد                                    | 100 جرام                                     | 100 جرام                                                                              |
| تكلفة رأس المال المستردة                         | 2,000 ريال                                   | لا تظهر                                                                               |
| الربح المتوقع الملغى                             | 400 ريال                                     | لا يظهر                                                                               |
| القيمة التجارية المرتبطة بالـ100 جرام وفق الصفقة | 2,400 ريال إذا كانت الصفقة موزعة خطياً بالسعر | يمكن إظهارها فقط كقيمة تسوية/استرداد للصفقة إذا كانت هذه هي السياسة التجارية المعتمدة |
| الوزن المتبقي لدى الموزع                         | 400 جرام                                     | 400 جرام                                                                              |
| التكلفة المتبقية للشركة                          | 8,000 ريال                                   | لا تظهر                                                                               |
| الربح المتوقع المتبقي                            | 1,600 ريال                                   | لا يظهر                                                                               |
| القيمة التجارية المتبقية                         | 9,600 ريال                                   | 9,600 ريال، قبل خصم الدفعات المدفوعة                                                  |

النظام يحسب الأثر الداخلي كاملاً، لكنه يرسل للموزع فقط الأثر التجاري المتفق عليه. بهذه الطريقة تبقى الشركة قادرة على مراقبة رأس المال والربح بدقة دون كشفهما خارجياً.

### 6. حساب الرصيد في تقرير الموزع

الرصيد الظاهر للموزع يجب أن يعتمد فقط على الالتزام التجاري للصفقة، وليس على تكلفة الشركة. القاعدة العامة المقترحة: الرصيد التجاري المتبقي = قيمة الصفقة المعدلة بعد الاستردادات والتسويات التجارية - إجمالي الدفعات المقبوضة. إذا كان هناك أكثر من طريقة لتسعير الاسترداد، تجعل هذه السياسة إعداداً قابلاً للتحديد في النظام.

### 7. إعدادات سياسة الاسترداد التجاري

| الإعداد                                 | الخيارات المقترحة                                                                  |
|----------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|
| طريقة تقييم الكمية المستردة تجاه الموزع | بنفس سعر الجرام في الصفقة / قيمة يحددها المستخدم عند الاسترداد / قاعدة أخرى معتمدة |
| هل يظهر سعر الجرام في تقرير الموزع؟     | نعم / لا                                                                           |
| هل يظهر سبب الاسترداد؟                  | نعم / لا                                                                           |
| هل يحتاج الاسترداد اعتماداً؟             | نعم / لا حسب الوزن أو القيمة                                                       |
| هل يسمح بالاسترداد بعد السداد الكامل؟   | حسب سياسة الشركة مع إنشاء تسوية مالية واضحة                                        |

### 8. مستويات حماية التقارير

- يجب أن يكون لكل قالب تقرير Report Type ثابت: INTERNAL أو DISTRIBUTOR.

- المستخدم الذي لا يملك صلاحية التقارير الداخلية لا يمكنه حتى معاينة حقول الربحية.

- الـPDF الخارجي يتم إنشاؤه من Dataset منفصل لا يحتوي أصلاً على الحقول السرية، بدلاً من إنشاء تقرير كامل ثم إخفاء بعض الأعمدة في الواجهة فقط.

- يظهر شريط واضح داخل شاشة المعاينة: «تقرير داخلي - سري» أو «تقرير موزع - خارجي».

- قبل تنزيل أو مشاركة التقرير الداخلي يمكن إظهار تحذير تأكيدي.

- يسجل Audit Log نوع التقرير، الصفقة، المستخدم، وقت الإنشاء، وهل تم تنزيله أو مشاركته.

### 11. اختبار منع تسرب بيانات الربحية

- إنشاء تقرير موزع لصفقة رابحة والتأكد أن كلمات التكلفة والربح والهامش ورأس المال لا تظهر في الملف أو بياناته المخفية.

- التأكد أن مستخدم بصلاحية Distributor Report فقط لا يستطيع الوصول إلى API أو Endpoint خاص بالتقرير الداخلي.

- التأكد أن تغيير القالب لا يضيف الحقول الداخلية عن طريق الخطأ.

- التأكد أن الاسترداد يظهر للموزع كحركة كمية وتسوية تجارية فقط، بينما يظهر أثر رأس المال والربح في التقرير الداخلي.

- التأكد أن تقرير الإغلاق الخارجي يعرض: الكمية الأصلية، المسترد، المسدد، المتبقي = صفر، وحالة مغلقة، بدون أي بيانات سرية.

### 12. تعليمات تنفيذية إضافية لـ Claude Coding

ابنِ التقارير الخارجية والداخلية كمسارين منفصلين على مستوى البيانات والصلاحيات، وليس كزر إظهار/إخفاء في الواجهة فقط. التقرير الخارجي للموزع يجب أن يستمد بياناته من DTO/View مخصص لا يحتوي على cost_per_g أو capital_cost أو expected_profit أو realized_profit أو margin أو partner data. عند كل إنشاء تقرير يسأل النظام المستخدم عن نوع التقرير ويعرض معاينة واضحة قبل التصدير. يجب إضافة اختبارات آلية تمنع تسرب أي حقل داخلي إلى ملفات الموزعين.

## 24. تحسينات التدقيق النهائية - V6

هذه الإضافات تحول الخطة من تصور أعمال قوي إلى مخطط تشغيلي محكم يقلل مساحة الاجتهاد أثناء البرمجة. المبدأ الرئيسي: الصفقة هي محور التعامل مع الموزع، والدفتر الحركي Ledger هو مصدر الحقيقة لكل رصيد وحالة، ولا تخزن الأرصدة النهائية كأرقام يدوية قابلة للتغيير.

### 24.1 الصفقة هي قلب النظام - Deal as the Core Object

- كل تسليم كمية لموزع ينشئ Deal مستقلة برقم واضح، ويمكن أن تحتوي الصفقة على سطر أو أكثر من الدفعات إذا سمحت السياسة بذلك، مع حفظ مصدر كل جرام على مستوى Deal Line.

- الصفقة تجمع الوزن، القيمة التجارية، الدفعات، الاستردادات، التسويات، المستندات، الملاحظات وحالة الإغلاق في Workspace واحد.

- أي شاشة أخرى في النظام تعرض ملخصاً للصفقة فقط؛ التفاصيل الأصلية تبقى داخل Deal Workspace وLedger الخاص بها.

- عند إعطاء نفس الموزع كمية إضافية يسأل النظام: إضافة للصفقة الحالية أو إنشاء صفقة جديدة. القرار يحفظ في سجل التدقيق.

### 24.2 دفتر حركات موحد للصفقة - Deal Ledger

بدلاً من تعديل أرصدة الصفقة مباشرة، كل تغيير ينشئ حركة Ledger. الأرصدة الحالية تحسب من مجموع الحركات المعتمدة، وهذا يجعل التدقيق وإعادة بناء الرصيد ممكناً في أي وقت.

| نوع الحركة            | الأثر الرئيسي                                                        |
|----------------------------------------------|---------------------------------------------------------------------------------------------|
| DEAL_OPEN             | إنشاء الصفقة وتثبيت الوزن والقيمة الأصلية                            |
| QTY_DELIVERED         | إضافة كمية للموزع من Lot محدد                                        |
| QTY_SOLD              | تخفيض الوزن المفتوح وإثبات التصريف                                   |
| PAYMENT_RECEIVED      | تخفيض الرصيد المالي فقط                                              |
| QTY_RETURNED          | إعادة كمية للمخزون وإلغاء قيمتها التجارية وربحها المتوقع حسب السياسة |
| COMMERCIAL_ADJUSTMENT | خصم أو إضافة تجارية معتمدة                                           |
| WEIGHT_ADJUSTMENT     | تسوية وزن بسبب موثق واعتماد                                          |
| PAYMENT_REVERSAL      | عكس دفعة دون حذف الحركة الأصلية                                      |
| CREDIT_TRANSFER       | نقل رصيد دائن إلى صفقة أخرى                                          |
| DEAL_CLOSE            | إغلاق الصفقة بعد المصالحة النهائية                                   |

### 24.3 حالتان منفصلتان لكل صفقة: الوزن والمال

لا تستخدم حالة واحدة مبهمة للصفقة. يجب فصل حالة التسوية الكمية عن حالة التسوية المالية، ثم اشتقاق الحالة العامة للصفقة منهما.

| المحور          | الحالات المقترحة                                                                |
|----------------------------------------|--------------------------------------------------------------------------------------------------------|
| Quantity Status | Open / Partially Settled / Fully Settled / Exception                            |
| Payment Status  | Unpaid / Partially Paid / Fully Paid / Credit Balance / Exception               |
| Deal Status     | Draft / Active / In Settlement / Ready to Close / Closed / Reopened / Cancelled |

- إذا كانت الدفعات كاملة لكن يوجد وزن مفتوح: الحالة العامة لا تكون Closed.

- إذا تمت تسوية الوزن بالكامل ويوجد مبلغ متبق: الحالة العامة لا تكون Closed.

- إذا نتج للموزع رصيد دائن، تظهر Payment Status = Credit Balance حتى تتم معالجته.

### 24.4 تخصيص الدفعات المالية - Payment Allocation

- عند تسجيل دفعة يحدد المستخدم هل الدفعة لصفقة محددة أو دفعة عامة على حساب الموزع.

- إذا كانت دفعة عامة، يسمح النظام بثلاث سياسات: توزيع على أقدم استحقاقات، توزيع يدوي، أو إبقاؤها كرصيد غير مخصص حتى يتم تخصيصها.

- لا يسمح أن تتجاوز تخصيصات الدفعة قيمة الدفعة نفسها.

- كل تخصيص Payment Allocation مستقل ويمكن عكسه دون حذف أصل التحصيل.

- كشف الموزع يعرض بوضوح الدفعات والتخصيصات والأرصدة غير المخصصة إن وجدت.

### 24.5 معالجة الرصيد الدائن للموزع

يجب دعم الحالة التي يدفع فيها الموزع مبلغاً ثم تسترد الشركة كمية تؤدي إلى خفض قيمة الصفقة تحت المبلغ المدفوع. الفرق لا يضيع ولا يسجل كربح للشركة، بل يتحول إلى Distributor Credit.

مثال: قيمة صفقة 12,000 ريال، تم دفع 8,000 ريال، ثم استردت الشركة كمية تخفض القيمة المعدلة للصفقة إلى 6,000 ريال. يصبح للموزع رصيد دائن 2,000 ريال.

| طريقة معالجة الرصيد الدائن | الأثر                                       |
|---------------------------------------------------|--------------------------------------------------------------------|
| Refund                     | إعادة المبلغ للموزع وتسجيل حركة دفع خارجة   |
| Transfer to Another Deal   | نقل الرصيد إلى صفقة أخرى لنفس الموزع        |
| Keep as Distributor Credit | الاحتفاظ به كرصد دائن مفتوح لاستخدامه لاحقاً |
| Authorized Adjustment      | تسوية أخرى تحتاج سبباً واعتماداً              |

### 24.6 شاشة المصالحة والإغلاق النهائي - Deal Settlement

قبل الإغلاق يعرض النظام شاشة مصالحة واحدة لا تسمح بالإغلاق إلا بعد تفسير كل جرام وكل ريال.

| بند المصالحة                         | يجب أن يساوي                                 |
|-------------------------------------------------------------|---------------------------------------------------------------------|
| الوزن الأصلي                         | مباع/مصرف + مسترد + تسوية معتمدة + وزن مفتوح |
| القيمة التجارية المعدلة              | دفعات مخصصة + رصيد متبق + رصيد دائن/تسوية    |
| الوزن المفتوح عند الإغلاق            | صفر                                          |
| الرصيد المالي غير المسوى عند الإغلاق | صفر إلا بحركة تسوية نهائية معتمدة            |
| الفروقات غير المفسرة                 | صفر                                          |

- الإغلاق ينشئ Closing Snapshot غير قابل للتغيير بصمت.

- أي تعديل بعد الإغلاق يحتاج Reopen بصلاحية مدير أو حركة عكسية وفق السياسة.

- عند إعادة الفتح يسجل السبب والمستخدم والتاريخ وتظل نسخة الإغلاق السابقة محفوظة.

### 24.7 تقرير التسوية النهائي للموزع

عند إغلاق Deal يستطيع النظام إنشاء تقرير خارجي مختصر يثبت إقفال التعامل دون كشف أي بيانات داخلية. يحتوي: رقم الصفقة، الصنف، الكمية الأصلية، الكمية المستردة، القيمة التجارية المعدلة، الدفعات، أي رصيد دائن تمت معالجته، الرصيد النهائي صفر، وحالة Closed وتاريخ الإغلاق.

### 24.8 المرفقات وسجل النشاط - Attachments & Activity Timeline

- كل حركة مالية أو كمية يمكن أن تحمل مرفقاً: إيصال، تحويل، صورة استلام، مستند تسليم أو إثبات استرداد.

- المرفق يخزن بمرجع ثابت ولا يستبدل الملف القديم عند رفع نسخة جديدة؛ بل تحفظ النسخ.

- يوجد Timeline موحد داخل الصفقة يجمع الحركات النظامية والملاحظات اليدوية.

- الملاحظة لا تغير الرصيد لكنها تسجل المستخدم والتاريخ ويمكن وسمها كمتابعة أو وعد دفع أو ملاحظة داخلية.

- يمكن جعل بعض الملاحظات داخلية فقط وبعضها قابلاً للظهور في تقرير الموزع عند اختيار ذلك صراحة.

### 24.9 تعريف المراحل الثلاث للربح

لمنع الخلط بين الربح والذمم والنقد، يحتفظ النظام بثلاثة مؤشرات مستقلة طوال دورة الصفقة:

| المؤشر                   | متى يظهر                                                |
|-------------------------------------------------|--------------------------------------------------------------------------------|
| Expected Profit          | عند إنشاء الصفقة بناءً على القيمة التجارية مقابل التكلفة |
| Earned / Realized Profit | عند إثبات أن الكمية تم تصريفها/بيعها وفق سياسة النشاط   |
| Cash Realized            | عند استلام النقد فعلياً من الموزع                        |

يجب أن تكون لحظة انتقال الربح من Expected إلى Earned إعداداً نظامياً واضحاً، مع توصية بأن يكون عند تسجيل QTY_SOLD/التصريف الفعلي، بينما Cash Realized يبقى مؤشراً مستقلاً مرتبطاً بالتحصيل.

### 24.10 لوحة السيولة والمركز التشغيلي - Cash Position

تضاف لوحة مالية مبسطة توضح أين توجد قيمة النشاط فعلياً، حتى لا يبدو وجود ربح محقق وكأنه سيولة متاحة للسحب.

| الأصول التشغيلية              | الالتزامات/الحقوق        |
|------------------------------------------------------|-------------------------------------------------|
| النقد المتاح في الصندوق/البنك | أرصدة الشركاء المستحقة   |
| ذمم الموزعين                  | الأرصدة الدائنة للموزعين |
| المخزون بالتكلفة داخل المخزن  | التزامات أخرى مسجلة      |
| المخزون بالتكلفة لدى الموزعين | -                        |

- Dashboard الرئيسية تعرض: Cash Available، Inventory at Cost، Distributor Receivables، Realized Profit، Expected Profit، Partner Payables.

- يجب ألا يستخدم Expected Profit في احتساب النقد المتاح أو الأرباح القابلة للسحب.

- تظهر قيمة المخزون في المخزن وقيمة المخزون لدى الموزعين بشكل منفصل.

### 24.11 تنبيهات ذكية وإدارة الاستثناءات

- Deal لم تسجل عليها دفعة منذ عدد أيام قابل للتحديد.

- صفقة مدفوعة بالكامل لكن وزنها غير مسوى.

- وزن الصفقة مسوى بالكامل لكن يوجد رصيد مالي.

- موزع لديه رصيد دائن غير معالج.

- موزع تجاوز حد العهدة/الائتمان.

- صفقة مفتوحة أكثر من الحد الزمني المحدد.

- مخزون Lot وصل إلى حد إعادة الطلب.

- فرق Reconciliation في الوزن أو المال.

- شريك سحب أكثر من الأرباح المستحقة له.

- مقدم أرباح لشريك لم تتم تسويته بعد إقفال فترة أرباح.

- تقرير داخلي تم إنشاؤه أو تنزيله بواسطة مستخدم ذي صلاحية حساسة.

## 26. قواعد حسابية إلزامية - Single Source of Truth

- لا تخزن قيمة الرصيد المتبقي للصفقة كحقل يدوي؛ تحسب من القيمة التجارية المعدلة ناقص التخصيصات والتسويات.

- لا تخزن الوزن المفتوح كقيمة يدوية؛ يحسب من الحركات الكمية المعتمدة.

- لا تخزن رصيد الشريك كرقم قابل للتعديل؛ يحسب من Partner Ledger.

- لا تخزن رصيد الموزع الإجمالي كرقم منفصل؛ يحسب من الصفقات والدفعات والأرصدة الدائنة.

- يمكن استخدام Cached/Materialized Values للأداء فقط بشرط وجود آلية Rebuild ومطابقة مع Ledger.

- كل Dashboard يجب أن يستمد أرقامه من نفس Views/Services المستخدمة في التقارير، لمنع اختلاف الأرقام بين الشاشات.

## 29. معايير الجاهزية للمرحلة الأخيرة - Technical Build Specification

- تم تثبيت أن Deal هي الوحدة المحورية للتعامل مع الموزع.

- تم تثبيت مبدأ Ledger لكل من الصفقة والشريك وعدم تعديل الأرصدة مباشرة.

- تم فصل حالة الوزن عن حالة السداد.

- تم تعريف الاسترداد الكمي وأثره على رأس المال والربح المتوقع.

- تم تعريف حالات المبالغ المدفوعة الزائدة والرصيد الدائن.

- تم تعريف إغلاق الصفقة والمصالحة النهائية.

- تم فصل التقارير الداخلية عن تقارير الموزعين على مستوى البيانات والصلاحيات.

- تم تعريف الربح المتوقع والمحقق والنقد المحصل كمراحل منفصلة.

- تم تعريف لوحة السيولة والتنبيهات والاستثناءات.

- تم إضافة اختبارات قبول تغطي الحالات الطبيعية والحالات الحدية.

بعد V6 تصبح المرحلة التالية هي تحويل هذه الخطة إلى Technical Build Specification تفصيلية: ERD، Data Dictionary، State Machines، API Contracts، Permission Matrix، Screen-by-Screen UX، معادلات KPI رسمية، Validation Rules، Migration/Seed Plan، واختبارات Unit/Integration/E2E. في تلك المرحلة يجب ألا يترك أي منطق أعمال رئيسي لاجتهاد أداة البرمجة.

## 30. تعليمات نهائية لـ Claude Coding قبل بدء التنفيذ

اعتبر DealLedger وPartnerLedger مصدر الحقيقة للحركات، ولا تسمح بتغيير الأرصدة أو التاريخ المالي مباشرة. نفذ تحديثات الوزن والمال داخل Database Transactions ذرية. افصل Payment عن Payment Allocation. افصل Distributor Credit عن Revenue. افصل Expected Profit عن Earned Profit وعن Cash Collected. امنع إغلاق Deal حتى تصبح المصالحة الكمية والمالية بلا فروقات غير مفسرة. أنشئ Internal DTOs وDistributor DTOs منفصلة للتقارير. كل State Transition حساس يجب أن يمر عبر Service/Stored Procedure واحدة مع Permission Check وAudit Log. قبل بناء الواجهات النهائية، اجعل اختبارات السيناريوهات المذكورة في هذه الخطة ناجحة بالكامل.
